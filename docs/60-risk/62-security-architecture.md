## 1. The architectural security dividend

Before the controls, the structural facts — because they eliminate whole vulnerability
classes rather than mitigating them:

| Absent by design | Class eliminated |
|---|---|
| **No LLM in the server** | Server-side prompt injection. Model-mediated SSRF. Tool-use abuse. Indirect injection through retrieved documents. **This is a large and currently fashionable attack surface that simply does not exist here** |
| **No EGW corpus** | Bulk content exfiltration. Corpus-poisoning. The entire class of "attacker downloads the valuable dataset" |
| **No file upload** | Malicious file parsing, archive bombs, path traversal on upload, malware hosting, image-parsing CVEs |
| **No server-side fetching of user URLs** | SSRF, cloud-metadata theft, internal port scanning |
| **No AI provider credentials anywhere** | Provider key theft, and the billing catastrophe that follows |
| **No card data** | PCI scope |
| **No public sharing at MVP** | Accidental exposure of private conversations by link |

A security reviewer should start here. Much of what they would normally hunt for is not
present to be found.

## 3. Authorization (the most important application control)

```ts
authorize(actor, action, resource) → Decision
```

Rules, in order of importance:

1. **Single entry point.** A route handler containing its own ownership check is a
   code-review rejection. Scattered authorization is how IDOR happens.
2. **Ownership in the query predicate as well as the decision.** Even if the decision layer
   is bypassed, `WHERE id = $1 AND user_id = $2` returns nothing.
3. **404, not 403**, for resources the actor may not see. A 403 confirms existence.
4. **Entitlements share the same module**, so a tier change cannot be enforced in one place
   and forgotten in another.
5. **Automated sweep.** A test enumerates every route accepting a resource id and asserts
   that a non-owner receives 404. New routes without coverage fail CI. This is the single
   highest-value security test in the suite.

## 4. Input handling

| Vector | Control |
|---|---|
| All request bodies | Zod schema at the boundary; unvalidated input never reaches business logic |
| Size | 64 KB per request; 8,000 chars per source block; 40,000 chars per conversation source total |
| SQL | Parameterised queries only via the ORM; raw SQL requires review and never interpolates input |
| **Pasted AI answers** | **Treated as fully untrusted data.** Rendered as sanitised Markdown — never `innerHTML`, never raw HTML, no `<script>`, no `javascript:`/`data:` URLs, no inline event handlers. Links get `rel="noopener noreferrer"` and an interstitial for unknown hosts |
| Pasted source text | Same rendering rules. Stored verbatim (fidelity matters); rendering is where safety is applied |
| User-supplied URLs | Scheme must be `https`; no credentials; private, loopback, and link-local addresses rejected; **never fetched by the server**; shown with an interstitial |
| Filenames in export | Generated by us, never derived from user content |
| Markdown | Allowlist renderer: headings, emphasis, lists, blockquote, code, links, tables. No HTML passthrough |

**On rendering pasted content:** this is the highest-risk rendering path in the product,
because the content originates from a system we do not control and may itself have been
manipulated by an attacker who put text into a shared document the member's AI then read. The
answer is a strict allowlist renderer plus a CSP that would contain a failure.

## 5. Output and transport controls

| Control | Value |
|---|---|
| CSP | `default-src 'self'; script-src 'self' 'nonce-{n}'; style-src 'self' 'nonce-{n}'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; form-action 'self'; base-uri 'none'; object-src 'none'` |
| CSP (conditional, BYOK) | *If* BYOK is ever unblocked ([ADR-0020](../90-decisions/adr/0020-byok-conditional-on-official-support.md)), `connect-src` additionally enumerates exactly the permitted provider API endpoints — nothing wildcarded |
| HSTS | `max-age=31536000; includeSubDomains; preload` |
| Frame | `frame-ancestors 'none'` + `X-Frame-Options: DENY` |
| Referrer | `strict-origin-when-cross-origin` |
| Permissions-Policy | camera, microphone, geolocation, payment all denied |
| COOP / CORP | `same-origin` |
| Cookies | `__Host-` prefix, `HttpOnly`, `Secure`, `SameSite=Lax` |
| CORS | No cross-origin API access. Same-origin only |

No inline scripts, no `unsafe-inline`, no `unsafe-eval`. A nonce-based CSP is the practical
mitigation that keeps a rendering flaw from becoming a session theft — or, if BYOK were ever
unblocked, an API-key theft. That second risk is one reason BYOK is now conditional rather
than scheduled.

## 6. Rate limiting and abuse

| Surface | Limit |
|---|---|
| Login | 5 / 15 min per (IP, account); 20 / 15 min per IP |
| Registration | 3 / hour per IP |
| Password reset | 3 / hour per account; 10 / hour per IP |
| Prompt generation | Entitlement quota + 60/hour fair use |
| Verification creation | Entitlement quota + 30/hour |
| Export | 3 / day |
| Conversation creation | 100 / day |
| Source block creation | 50 / day |
| All authenticated writes | 300 / 5 min per user |
| Global | Cloudflare rate rules |

Export deserves note: a hijacked session's most damaging action is bulk exfiltration of the
member's own history. Rate limits plus audit plus an email on export are the countermeasures.

## 7. Secrets

- Platform secret store only. Never in the repository, never in the container image, never in
  logs, never in error reports.
- Secret scanning in CI on every commit, including provider-key format patterns for OpenAI,
  Anthropic, and Google — a hit fails the build, which also serves the Cost Firewall.
- Rotation: master key annually with DEK re-wrap; session secret quarterly; provider keys
  quarterly; database credentials on any incident.
- **The master key is the crown jewel.** Access is limited to the production runtime and one
  sealed offline escrow copy. Its loss is unrecoverable for message bodies; its theft, combined
  with a database copy, exposes everything in Standard mode.

## 8. Audit logging

```
audit_event: at · actor · actor_role · action · resource_type · resource_id ·
             target_user · ip_prefix · metadata(allowlisted scalars) · prev_hash · hash
```

- Append-only: the application role has `INSERT` and `SELECT`, no `UPDATE`, no `DELETE`.
- `hash = SHA-256(prevHash ‖ canonical(event))`. A daily job verifies the chain and alerts on
  a break.
- `metadata` keys are allowlisted, so user content cannot be written here even by accident.
- Audited: authentication events, password and 2FA changes, session revocations, membership
  changes, admin actions, break-glass access, config and template changes, exports, deletions,
  consent grants and withdrawals, **egress denials**, and rate-limit lockouts.

A small dependency tree is a security control in its own right, and this application's
requirements make one achievable — there is no model client, no document parser, no upload
pipeline, and no vector library to pull in.

## 10. Frontend-specific concerns

- **Clipboard.** Write-only via `navigator.clipboard.writeText()` on a user gesture. **We
  never read the clipboard.** Reading it in a product handling private material would be
  indefensible, and it is also unreliable across browsers.
- **Browser storage.** At MVP: UI preferences only. Never session tokens (they are HttpOnly
  cookies). BYOK would add the key, session-scoped by default, with its own consent — but it is
  conditional and unbuilt ([ADR-0020](../90-decisions/adr/0020-byok-conditional-on-official-support.md)).
- **Provider tabs.** Opened with `rel="noopener noreferrer"` so the opened page cannot reach
  `window.opener`. No message passing, no polling, no automation.
- **Malicious browser extensions.** Cannot be prevented by a web application. Mitigations:
  strict CSP limits what injected script can exfiltrate to; sensitive actions require
  re-authentication; the honest statement in the security documentation is that an extension
  with page access can read anything the member can see. Members handling highly sensitive
  material are advised to use a clean profile — advice, not a control, and labelled as such.

## 12. Incident response

| Severity | Definition | Response |
|---|---|---|
| **S1** | Confirmed unauthorised access to user content; master key compromise | Immediate: rotate secrets, revoke all sessions, preserve evidence, engage counsel, notify affected users and regulators within statutory windows |
| **S2** | Vulnerability enabling S1; provider breach affecting our data | Patch within 24 h; assess exposure; notify if content was reachable |
| **S3** | Account takeover of a single user; abuse | Lock the account, revoke sessions, force reset, notify that user |
| **S4** | Low-impact finding | Ticket and schedule |

Every incident produces a written post-incident review with a timeline, root cause,
contributing factors, and actions — retained and, for S1/S2, summarised publicly. For a
product whose pitch is honesty, a quiet incident would be a contradiction of the pitch.

## 13. Residual risks, stated plainly

| Risk | Why it remains | Mitigation |
|---|---|---|
| Compromised application server can decrypt Standard content | The master key must be in memory to serve the product | Hardened runtime, minimal image, secret rotation, Ephemeral and Private modes for content where this matters |
| Malicious operator | Someone must be able to run the system | Audit, unsuppressable break-glass notice, no bulk content access, monthly review |
| Malicious browser extension | Outside our boundary | Strict CSP, honest documentation |
| Provider-side exposure of what the member pastes | Outside our boundary entirely | Disclosure, consent, Ephemeral alternative, local-only P2 drafting |
| Legal compulsion | Ciphertext we can decrypt is ciphertext we can be ordered to decrypt | Stated in the policy; Private mode (Horizon 2) removes the capability |
| Master key loss | Concentrated risk is the cost of envelope encryption | Sealed offline escrow, rehearsed |
